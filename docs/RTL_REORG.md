# RTL map

Where each SystemVerilog module lives and what it does. Coding rules: [RTL_DESIGN_PRINCIPLES.md](RTL_DESIGN_PRINCIPLES.md). Build and resource limits: [FPGA_FIT.md](FPGA_FIT.md). Plugs: [USB_KEYBOARD_PMOD_MICE.md](USB_KEYBOARD_PMOD_MICE.md).

## Two tops, two file lists

| Target | Top module | File list |
|---|---|---|
| Simulator (`make -C sim sim_server_synth`) | `jmr_js_core` | `CORE_SRCS` in `sim/Makefile` |
| Board (`tools/board_flow`) | `top_nexys_video`, which wraps the same `jmr_js_core` | `jmr_add_sources` in `tools/board_flow/vivado_build.tcl` |

A file added to only one list is missing from the other machine.

Core parameters:

| Parameter | Simulator | Board | Meaning |
|---|---|---|---|
| `SRAM_INTERNAL` | 1 | 0 | 1 puts `jmr_sram_model` inside the core. 0 exposes the memory port to the DDR3 bridge. |
| `FRAME_DIV` | 65535 | 1666665 | Clocks per frame tick. The board value gives 60 Hz. |
| `BOOT_CLOCK_HZ` | 1000000 | 100000000 | Length of the startup screen only. |
| `VM_CLK_DIV` | 3 | 3 | The VM clock is the 100 MHz clock gated to one edge in three (33.333 MHz). Everything else stays on 100 MHz. |

`$readmemh` paths are relative to the `.sv` file. The `.hex` files under `rtl/engines/` and `rtl/video/` are copies the board build makes from `vectors/`. Edit the ones in `vectors/`.

## Top level

| File | What it is |
|---|---|
| `rtl/jmr_js_core.sv` | The machine: VM, loader, storage, picture, input queues. Shared by simulator and board. |
| `rtl/top_nexys_video.sv` | Board shell: clocks and reset, DDR3 controller and bridge, HDMI, keyboard, mice, joystick, SD pins, tether, audio, LEDs. |

## `rtl/engines/` — in the machine

| Module | What it does |
|---|---|
| `jmr_js_vm` | The JavaScript VM. Holds the one heap, the code memory, the Toolbox instruction bank and the garbage collector. |
| `jmr_js_vm_exec64` | The only opcode and native-call decoder. Instantiated inside `jmr_js_vm`. Owns no arrays. |
| `jmr_js_vm_pkg` | VM state enum, opcode ids, capacity constants. |
| `jmr_value` (`jmr_value_pkg`) | Value64 number and tag helpers. |
| `jmr_toolbox_rom_pkg` | Identity of the linked Toolbox. Generated by `tools/toolbox_linker.py`. |
| `jmr_toolbox` | Toolbox hardware primitives: memory move and fill, blit, CopyBits, raster and mask, typed memory, scissor. |
| `jmr_console_engine` | Loader. Program, SOURCE, compiler and file-transfer services for Finder and the host tether. No command parser or prompt. |
| `jmr_finder_shell` | Supervisor. Launches programs on request and returns to Finder when a program exits or fails. Holds the exit status Finder reads through `sysDocument`. |
| `jmr_finder_fs` | File services for programs. |
| `storage_engine` | FAT32 file operations. Instantiates `sd_spi_master`. |
| `jmr_mini_fb` | The 640×480, 8-bit draw canvas in block RAM. |
| `jmr_raster_engine` | Rectangle, blit and ImageData writes into the canvas at 100 MHz. |
| `jmr_fb_present` | Copies the canvas to the front image in external memory. |
| `jmr_fb_scanout` | Reads the front image ahead of the beam into two line buffers for HDMI. |
| `jmr_palette_bram` | 256-entry RGB palette. |
| `jmr_video_vram` | 64×16 character memory for the recovery text display. |
| `jmr_mouse_events` | Turns pointer samples into ordered JavaScript mouse events. |
| `jmr_system_menu`, `jmr_system_menu_pkg` | System menu and on-screen keyboard controller. The package is generated by `tools/export_system_menu.py`. |
| `jmr_ui_snapshot` | Carries a bundle of UI state from the 100 MHz clock to the pixel clock. The same file holds `jmr_resource_bridge`, which carries `SYSTEM.SYS` words across. |
| `jmr_classic_ui_pkg` | Layout constants and helper functions. Generated by `tools/export_classic_ui.py`. |
| `jmr_classic_static_labels` | Caption records for `jmr_classic_overlay`. |
| `jmr_rectdemo_engine` | Fixed RECTDEMO rectangle painter. |
| `jmr_sram_model` | Simulator model of the 8 MiB external memory. |

## Shared and copied files

| File | Also compiled by |
|---|---|
| `rtl/phys/ps2_rx.sv` | `tools/hid_led_blink/`, `tools/pmod_input_test/`, `tools/mouse_probe/` |

An edit to one of these changes the probe bits too. The simulator does not compile the `phys/` receivers, so it will not show the change.

`tools/pmod_input_test/` and `tools/audio_beep_test/` hold their own copies of `jmr_i2c_joy.sv`, `jmr_i2c_master.sv` and `jmr_adau1761_cfg.sv`. The machine uses the ones in `rtl/phys/`.

The probe folders build their own tops. Never add them to either file list. How to run them: [FPGA_BRINGUP.md](FPGA_BRINGUP.md#probe-bits).

## State names

The VM state enum exists in three places that must match: `jmr_js_vm.sv`, `jmr_js_vm_pkg.sv`, and `vm_sname()` in `sim/sim_main.cpp`. `runtime/vm_state_names.py` is the Python copy. When a state is removed, renumber all four together; the simulator also compares a few state numbers directly, so search `sim_main.cpp` for the old values. The console and storage enums use explicit numbers.

Check the RTL and C++ lists:

```bash
python3 - <<'EOF'
import re
def enum(p):
    L=open(p).read().split("\n"); k=next(i for i,l in enumerate(L) if "typedef enum logic [6:0]" in l)
    o=[]
    for l in L[k+1:]:
        if "st_t" in l and "}" in l: break
        o+=[t.strip() for t in re.sub(r"//.*","",l).split(",") if t.strip().startswith("S_")]
    return o
def cpp():
    c=open("sim/sim_main.cpp").read(); i=c.index("static const char* vm_sname")
    j=c.index("};", i)
    return re.findall(r'"(S_[^"]+)"', c[i:j])
par, pkg, names = enum("rtl/engines/jmr_js_vm.sv"), enum("rtl/engines/jmr_js_vm_pkg.sv"), cpp()
print("parent", len(par), "pkg", len(pkg), "c++", len(names), "| equal:", par==pkg==names)
EOF
```
